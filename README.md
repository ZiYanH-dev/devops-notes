# DevOps · 部署与运维

> **主线**：从代码完成到线上稳定运行，整条链路所需的全部环节。

> 一句话：**把代码变为持续可用的线上服务**的技能集合。

## 全貌图（一条部署链路）

```
物理服务器
    ↓
用软件创建多台虚拟机
    ├── 虚拟化/虚拟机（Hypervisor）← 00
    ↓
开发写了代码
    ↓
打包成标准单位
    ├── Docker（容器）← 01
    ↓
运行单个容器简单，成百上千个容器需要编排
    ├── Kubernetes（编排）← 02
    ↓
手动重复构建与部署成本高 → 自动化
    ├── CI/CD（流水线）← 03
    ↓
    代码推送后先验证，未通过不上线
    ├── 测试（质量保证）← 08
    ↓
    入口流量需要分发、缓存与加密
    ├── Nginx（反向代理/Web服务器）← 04
    ↓
代码与服务器部署在何处
    ├── 云平台（IaaS/PaaS/Serverless）← 05
    ↓
日志、监控、报警 → 线上稳定运行
    ├── 可观测性（Logs/Metrics/Traces）← 07
    ↓
配置、密钥与环境的管理（横切）
    ├── 配置管理（Config/Secret）← 09
    ↓
线上稳定运行 ← README 本篇总纲
```

## 两个核心理念

1. **一切皆交付**：DevOps 目标 = 快速且稳定地把代码交付到线上
2. **按需抽象**：本地直接运行 → 容器 → 编排 → 平台，抽象层次越高，人工干预越少

## 云原生：串起这一切的理念总纲

**云原生 = 为运行于云上并充分利用云特性而设计的软件方法论。**

它不是软件、不是框架、不是代码实现，而是一套**设计原则的集合**。本目录里的每个工具，都是把云原生理念落地的具体手段。

| 云原生原则       | 用什么实现                       |
| ----------- | --------------------------- |
| **容器化打包**   | Docker → 环境一致               |
| **编排调度**    | Kubernetes → 自动扩缩容、自愈       |
| **自动化交付**   | CI/CD → 推代码自动部署             |
| **不可变基础设施** | 不手动改机器，重建而不是修补              |
| **可观测性**    | 日志/Metrics/Traces → 确认运行是否正确 |
| **声明式配置**   | 配置进代码库，可版本管理（GitOps）|

> **一句话**：云原生是为云而设计的理念，
> Docker/K8s/CI/CD/监控都是把理念落地的工具。
> 抽象层次越高、人工干预越少，正是这套理念的目标。
