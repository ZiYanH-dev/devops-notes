# DevOps · 部署与运维

> **主线**：
> 从"代码写好"到"线上稳定运行"，这一整条链路需要的东西。

> 一句话：**把代码变成一直可用的线上服务** 的技能集合。

## 全貌图（一条部署链路）

```
物理服务器
    ↓
用软件切出多台假机器
    ├── 虚拟化/虚拟机（Hypervisor）← 00
    ↓
开发写了代码
    ↓
打包成标准单位
    ├── Docker（容器）← 01
    ↓
跑 1 个容器简单，成百上千个怎么管
    ├── Kubernetes（编排）← 02
    ↓
每次手动打包部署太累 → 自动化
    ├── CI/CD（流水线）← 03
    ↓
    代码一推先验证对不对，跑不过不上线
    ├── 测试（质量保证）← 08
    ↓
    入口流量要分发、要缓存、要加密
    ├── Nginx（反向代理/Web服务器）← 04
    ↓
代码和服务器放哪跑
    ├── 云平台（IaaS/PaaS/Serverless）← 05
    ↓
日志、监控、报警 → 线上稳定运行
    ├── 可观测性（Logs/Metrics/Traces）← 07
    ↓
配置、密钥、环境怎么管（横切）
    ├── 配置管理（Config/Secret）← 09
    ↓
线上稳定运行 ← README 本篇总纲
```

## 两个核心心智

1. **一切皆"交付"**：DevOps 目标 = 快而稳地把代码交付到线上
2. **按需抽象**：本地直跑 → 容器 → 编排 → 平台，越往上越省心、也越黑盒

## 云原生：串起这一切的理念总纲

**云原生 = 为"跑在云上、充分利用云特性"而设计的软件方法论。**

它不是软件、不是框架、不是代码实现，而是一套**设计原则的集合**。本目录里的每个工具，都是把云原生理念落地的具体手段。

| 云原生原则       | 用什么实现                       |
| ----------- | --------------------------- |
| **容器化打包**   | Docker → 环境一致               |
| **编排调度**    | Kubernetes → 自动扩缩容、自愈       |
| **自动化交付**   | CI/CD → 推代码自动部署             |
| **不可变基础设施** | 不手动改机器，重建而不是修补              |
| **可观测性**    | 日志/Metrics/Traces → 看它跑得对不对 |
| **声明式配置**   | 配置进代码库，可版本管理（GitOps）        |

> **一句话**：
> 云原生是"为云而设计"的理念，
> Docker/K8s/CI/CD/监控全都是把理念落地的工具。
> 越往上越省心、越黑盒，正是这套理念想要的结果。
